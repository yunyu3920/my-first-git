# 图片管线（temu-bot images）

把表格里的原图变成 Temu 能收的合规图。代码在 `src/temu_bot/imaging/`。

## 规格从哪来的（别把推定当原文）

| 用途 | 目标尺寸 | 填充方式 | 体积 | 依据 |
|---|---|---|---|---|
| 主图/轮播图 | **1340×1785** | 充满裁剪（不留边） | ≤2MB | **平台报错原文** |
| 素材图 | **800×800** | 完整放入（补白边） | ≤2MB | 由现有数据反推（**推定**） |

主图规格有平台原文撑腰——2026-10-15 商品 `184807703165779045` 的真实 errMsg：

> 服饰类目skc轮播图[…]校验失败，应符合宽高比例为 **3:4**，宽 **>=1340px**，高 **>=1785px**，**<=2M**

素材图 800×800 是反推的：表里 98 行素材图都是 800×800，平台从没就它报错。
代码里 `MATERIAL_IMAGE.grounded = False`，打印时标「(推定)」，拿到平台原文再收紧。

**踩过的坑**：表里 98 行主图的尺寸分布是 68 行 1340×1785、29 行 1340×1786、
**1 行 1340×1784**——就那一行失败了。**矮 1 像素也不行。**

## 先"找图"，再"出图"

表格里写的是**图片文件名**，图在**图片文件夹**里。所以第一步是拿名字去文件夹里找——
这一步在 `imaging/resolve.py`，不在出图逻辑里硬拼路径。

匹配方式按可靠度从高到低，**只要不唯一就不猜**：

| 方式 | 场景 |
|---|---|
| `exact` | 完全一致（大小写也要一致） |
| `casefold` | 只有大小写不同 |
| `stem` | 扩展名不同（`.jpg` ↔ `.png`） |
| `recurse` | 图在子文件夹里 |
| `prefix` | 唯一的前缀匹配 |
| `ambiguous` | 匹配到多张 → **报错，绝不猜** |

> 为什么 `exact` 不写成 `(文件夹/名字).is_file()`：Windows 的文件系统**本身不区分大小写**，
> 那样 `abc.JPG` 会被当成精确命中，换到 Linux 上行为又不一样。
> 所以一律拿索引进比对，与操作系统无关。

图片文件夹从哪来：**默认用表里第 1 列「文件夹路径」**。`--images-dir` 是个可选覆盖项，
只在表里路径写错、或临时换一批图时才需要给。

## 三条硬约定

1. **原图只读**。绝不覆盖、绝不原地改，产出全落 `work/<row_key>/out/`。
2. **已合规就直通**。尺寸本来就合格时做**字节复制**，不重新编码，避免二次损失。
3. **写完当场复验**。产出后按规格再量一遍，不合格直接报出来，不等平台打回。

## 命令

```bat
:: 上架前：验表格与表里指出的图片位置（只读）
temu-bot preflight

:: 只读：看这一行的图**能不能找到**、合不合规
temu-bot images check --row-index 32

:: 出图（默认干跑，--live 才落盘；只写 work/，原图绝不动）
temu-bot images prep --row-index 32 --live

:: 只在表里路径写错/临时换一批图时才需要显式指定
temu-bot images prep --row-index 32 --images-dir "D:\新图" --live

:: 打印当前规格与其依据
temu-bot images specs
```

产出目录里会带一份 `manifest.json`，记着每张图的来源、处理方式、前后尺寸与问题，
方便回头查"这批图是怎么来的"。

## 在主流程里的位置

```
PRECHECK → MEDIA(出图) → SHOP_CHECK → FIND_TEMPLATE → COPY → FIND_NEW → APPLY
```

MEDIA 排在碰网络之前——图片不合格是本地就能查出来的事，没必要等到被平台打回。
干跑只出计划不落盘；`run --live` 时才会真的写出文件。

## 上传与换图（已接通）

出图是本地准备，之后由主流程的 `UPLOAD` 步把图传到店小秘、`APPLY` 步把地址写进商品：

```
MEDIA（本地出图）→ UPLOAD（传 COS + 登记）→ APPLY（换图 + 改标题 + 保存）
```

- 三个接口的参数**已经实探到了**（不是猜的）：`POST /api/cos/getSign.json`（`bucket` +
  `region`）→ `PUT` COS → `POST /api/cos/cosDxmCallBack.json`（登记）。
- 换图要写哪几个字段、以及"那几个字段其实是 JSON 字符串"这个大坑，
  见 **`docs/图片上传.md`**。
- 换图**一处都没写进商品字段**时，`APPLY` 会直接 `FAIL` 中止——不会存下一个
  "标题对、图片是模板的"错商品。

这样"出图 → 换图 → 发布"就串成一条线了。
