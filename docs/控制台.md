# 本地网页控制台

照原工具（`自动工具1.66`）的界面模式做的本机控制台：左边菜单、中间参数、右边实时日志。

```bat
0-启动 temu-bot.bat           :: 双击即用，会自动打开浏览器
temu-bot serve                :: 等价命令（--port 8765 --no-open 可调）
```

**只 bind `127.0.0.1`**，并对 `Host` / `Origin` 做校验——本机服务最怕的是你浏览器里
某个网页偷偷打 `http://127.0.0.1:8765`（DNS rebinding / CSRF）。所以：
- 非本机的 Host 直接 403
- 带非本机 Origin 的请求直接 403
- 不接受 `0.0.0.0`，`serve()` 会直接拒绝
- 不引 CORS 中间件

> **改了 `src/` 下的 Python 代码，必须重开控制台**：后端路由是进程启动时定死的，
> 只刷新页面没用（页面的 HTML/JS 是每次从磁盘现读的，所以看着是新的）。
> 真忘了重开，接口会回 404，页面会直接提示"多半是还开着旧进程"。

### 选路径：直接弹系统的文件窗口

点「选择表格」/「选择文件夹」/「另存为…」会打开**系统的文件对话框**（资源管理器样式），
不是网页里自制的目录树。

为什么得这么绕：**浏览器出于安全不允许网页拿到本地真实路径**
（`<input type="file">` 只给文件名，`showDirectoryPicker()` 也给不出绝对路径）。
但咱们的服务就跑在本机上，所以改由 **后端** 去调 Windows 的文件对话框，再把路径回给页面。

实现见 `src/temu_bot/web/dialogs.py`：

- 用 shell32 的 `IFileDialog` + `FOS_PICKFOLDERS`，即**现代资源管理器样式**
  （左侧导航栏、顶部路径栏、按钮写「选择文件夹」），不是 `SHBrowseForFolder` 那种老式小树。
- PowerShell 脚本用 `-EncodedCommand`（base64/UTF-16LE）传，**躲开引号转义的地狱**。
- 子进程有超时（默认 600 秒），用户把对话框晾着不管也不会把服务卡死。
- **同时只允许一个对话框**，第二个请求会收到 409。
- 请求会一直挂着直到用户选完——所以按钮会变成「等待选择中…」并禁用。
- 万一弹不出来（没有桌面会话等），页面会**自动退回站内目录树**，不会卡死。

安全性：这几个接口同样受「只允许本机」的 Host/Origin 校验保护——
**别的网页不能诱导你本机弹对话框**。

### 收集文件页

按 ①②③ 三步：**选素材与店铺 → 素材图设置 → 扫描并生成**。

- 选文件夹（选择器里点「就用这个文件夹」）
- 店铺名、模板 spu、主图索引（店铺名填的是配置里有的店，会自动带出模板 SPU）
- **店铺名与模板 SPU 会记住上次填的**（存在浏览器本地 `localStorage`，键
  `temu_bot.collect.last`）：下次打开自动带出来，不用每次重填。
  从没填过时**留空**——不会拿配置里那家"配了模板SPU"的店来凑数
  （配置是死的，那家店很可能是早就停用的，填上去只会让人以为程序认错了店）。
  换店时直接改就行，改完立刻记住。
- 「以图片名作为 SKC 货号」勾选框
- 素材图宽高 + 「强制生成素材图」（**默认勾上** = 缺素材图就用主图生成一张；
  不勾 = 缺素材图就跳过该行）
- **先「扫描预览」**（只读，不写文件）：列出会收成哪些行、跳过哪些、写到哪个路径
- 再「生成表格」

生成完可以直接点「用这张表上架」，把它设成当前商品信息表。
细节见 `docs/收集图片.md`。

### 自动上架页

按 ①②③ 三步走：

**① 选择表格** —— 只需要给表格。图片位置由表里给：第 1 列是「文件夹路径」，
各图片列是文件名，工具按这些名字去那个文件夹里**找**图
（找不到或匹配到多张都会在碰接口前挡下来）。

**② 选择要跑的行** —— 带搜索（行号/标题/店铺/主图/**SKU货号**）、状态筛选、"只看未成功"。
每行标出：

- **`已有商品`**（表里有商品ID）= 续跑，不会复制、不会重复传图 → **可以真跑**
- **`新建`**（没商品ID）= 会复制模板建新商品 + **换主图**
- **SKU货号**（第 9 列）：上架时填进每个 SKU 的货号。空的话显示红色 **`缺`** ——
  **没有它就跑不了**（不能沿用模板的货号，那会让一批商品共用一个号）

**③ 预览并运行** —— 勾选后这里显示这一行的：
- **主图缩略图**（真实图片，可以直接看出有没有配错图）
- **SKU 货号**（第 9 列）：有值标「会填进每个 SKU」，空的话标红并写明会被挡下
- 图片找没找到、合不合规、要不要重出（例如 `1340x1784 → 1340x1785`）
- 店铺、状态、是否已有商品

然后是运行方式（**默认「真实执行」**）、**上架前先打开店小秘**、**强制换图**、
**自动清理图片**、开始/停止。

### 不用选登录身份——程序按表格自己认

用户 2026-10-16 明确：**「我们登录，程序核对确认即可。舍弃多余操作
（登录身份的店铺输入框、核对店铺、打开店小秘按键）」**。

所以上架页**没有登录身份下拉框、没有「核对店铺」按钮、没有「打开店小秘」按钮**。
程序自己来：

```
表里第 10 列「SWEET SHIRT SHOP」
        ↓ 挨个问：哪个登录身份的账号里有这家店？（实时读 userIn）
   登录身份「hat-tshirt」→ 账号里有 SWEET SHIRT SHOP (shopId=8665618) ✅
        ↓
   用这个身份继续（复制/传图/保存都打在这家店上）
```

- **哪个身份：** 磁盘上真的有登录态的身份（`data/state/session_<身份>.json`，
  登录时才会生成），不是配置里那份静态店铺表——店铺不固定，配置随时会过期。
- **哪个账号有这家店：** 挨个实时问一遍 `userIn.shopMap`，谁有就是谁。结果缓存 20 秒
  （一批几十行、店铺名往往一样，不必每行都问）。
- **对不上就停**，并说清查过哪些身份、那些账号里实际有哪些店：

  ```
  ❌ SHOP_CHECK：表里要上「XXX」，但**没有任何登录身份的账号里有这家店**。
     查过的身份：hat-tshirt（账号里没有这家店）；lovely（没登录 / 登录态过期）。
     这些账号里见到过的店：A hat tshirt、A lovely costume。
     → 请到店小秘里确认这家店在哪个账号下，登录好之后把浏览器窗口关掉，再重新开始。
  ```

- **不去扫 `profiles/` 目录**：那里面除了真登录态还有一堆跑脚本留下的浏览器缓存，
  扫进来只会塞满没用的东西（真登录过的身份必然有会话文件，不会漏）。

> 页面上不再显示"当前用的是哪个身份"——它每次运行都按表算，可能都不一样。
> 想固定用某个身份，CLI 上仍可以 `--shop <身份>` 指定。

### 「上架前先打开店小秘」（默认勾着）

**上架之前程序自动把网站打开**，目的是①让你自己确认店铺信息对不对；
②需要的话当场**登录**或者**切换店铺**。

- 点「开始」后先弹浏览器（**按表格里的店铺名决定开哪个账号的浏览器**），
  然后照常开跑，页面顶部横幅会说明开的是哪个身份、为什么。
- **对不上就提醒并停止上架**：这时程序会顺手把店小秘打开（好让你当场登好账号），
  顶部横幅写明原因，改完再点「开始」。
- 干跑也会打开（好让你先把账号登好），不想开就把勾去掉。

**实现上是另起一个进程**跑 `temu-bot login --shop <身份> --until-closed`：

- 不在服务里直接用 Playwright——它的同步 API 有线程亲和性，在 FastAPI 的线程里
  长时间握着浏览器会话风险太大（服务一重启就可能留下一个死掉的浏览器）。
- 子进程没有终端可以按回车，所以走的是 **`--until-closed`：把浏览器窗口关掉就算完事**。
- **边等边存**：窗口开着的时候每 5 秒存一次登录态（cookie 只在浏览器还活着的时候
  读得到，等关了再存就晚了）。所以你在窗口里登录完，几秒内登录态就已经落盘了。
- 同一个身份**不许叠窗**；重复打开会提示"已经开着了"。

### 换图开关

「强制换图」默认**勾上**：每一行都重传图换图，包括表里已有商品ID 的"续跑"行。

不勾就是按行自动判断：

| 这行 | 不勾时的行为 |
|---|---|
| 表里**没有**商品ID（新行） | 把表里这几张图传到店小秘，换掉模板的主图 |
| 表里**已有**商品ID | **不换**：这是重试/续跑，重复传图只白占图片空间 |

勾不勾都**不会复制**已有商品的行（那是重复铺货）。

**换图的规矩（只换主图）**：新主图顶到轮播第 1 位，**模板的其它展示图保留不动**，
SKU 缩略图跟着换；**颜色/尺码一个字都不动**。详见 `docs/图片上传.md`。

### 为什么新行现在可以真跑了

以前这里有一道硬闸（`LIVE_NEW_ROW_ALLOWED = False`）：新行真跑会被 **409 拒绝**。
因为那时主流程复制出商品后**只改标题、不换图**，真跑会得到"标题是你表里的、图片是
模板的"错商品。

现在图片上传接通了（`docs/图片上传.md`），新行会真的换图；而"换图没写进去"这种情况
由**流水线自己**兜住——`APPLY` 会直接 `FAIL` 中止，什么都不会保存。所以粗闸门撤了，
`LIVE_NEW_ROW_ALLOWED = True`（`web/app.py`）。要临时关掉就改那个常量。

### 设置页

页面上能改的：**运行**（速度档位 / 日志级别 / 出错截图）、**浏览器**（无头 / 视口）、
**路径**（商品信息表 / 旧工具箱目录）。

**没有「店铺」那一块了**（用户 2026-10-16 要求删掉）——店铺名、登录身份、模板 SPU
一律由**表格**说了算，页面不该再摆一份配置出来诱导你去改。要动就改配置文件。

改动**只写 `config.local.yaml`**（本机覆盖层），主 `config.yaml` 与其注释分毫不动——
这一点有测试钉住（写前写后比对 SHA256）。写入前会先整体校验一遍 `Config`，
验不过就拒绝、不落盘；写前还会备份一份到 `data/backups/`。

**AI 密钥永远不在页面上显示**，只报"环境变量设没设"。

## 关于「停止」，说清楚它到底能停什么

`ListingPipeline.run()` 是同步阻塞的，而且**写了就不能半途停**：断在 COPY 之后、
APPLY 之前会留下一个"复制了但没改标题"的商品，product_id 也没落账 → 重跑就是重复铺货。

所以停止的语义是：

- **写操作开始之前**：在步骤之间停下（`CANCEL` 步会写清"此时还没执行任何写操作"）
- **写操作开始之后**：这一行必须跑完，之后不再开始新的行

按钮文案就是照这个写的（「停止（当前这一行会跑完）」），不假装按一下就能立刻中断。

## 日志

- 页面右侧是实时日志，走 SSE（`/api/logs/stream`）。
- 后端用「异步生成器 + `asyncio.sleep` 轮询」实现，**不用阻塞等待**——阻塞会卡住
  uvicorn 的 event loop（连带所有接口一起卡），而且断线时被阻塞的线程没法及时取消、会堆积。
- 重连靠 `Last-Event-ID` 续传：`EventSource` 重连时打的是同一个 URL，不认这个头
  就会每次重连都把整段日志重放一遍。
- 日志内容**一定 JSON 编码后再放进 `data:`**——日志里带换行会截断 SSE 帧。
- 另有 `GET /api/logs?after=<seq>` 轮询兜底（SSE 不通时页面可用它）。

## 商品ID/状态会写回表格（`WRITEBACK` 步）

真实跑完，主流程自己把 **商品ID（第 13 列）+ 状态（第 14 列）+ 问题项（第 16 列）**
写回表格——跑一行就锁一行，中途停了也记下做过的。
**这是防重复铺货的闸门**：表格里没有商品ID 的行，下次跑还是"新建"。

写表要过 `sheet/guard.py` 那套安全闸：先确认表没被 Excel/WPS 打开、写前备份、
落盘是原子替换。**表开着的时候写不成**——这时：

- `WRITEBACK` 那一步显示 ❌，但**上架结果不算失败**（商品已经建好了，
  说"失败"会诱使你去重跑，那正好造成重复铺货）；
- 页面顶部会单独弹一条横幅点名是哪几行没写回；
- 关掉表后补写：`temu-bot table writeback --live`。

另外每次运行还会把明细追加进 `data/state/runs.jsonl` 当账本——万一回写失败了，
`table writeback` 就是从它把成功过的行补上。

## 接口一览

```
GET  /                        页面
GET  /api/status              版本 / 表格行数 / 可用登录身份 / 任务状态
POST /api/browser/open        打开店小秘（传 shop=<表格店铺名>，程序自己认开哪个身份）
GET  /api/browser/status      那个窗口还开着吗
POST /api/shops/verify        核对：表里用到的店名 ↔ 登录账号里实际的店（CLI/排查用）
GET  /api/config              可编辑配置摘要（密钥只报设没设）
POST /api/config              写 config.local.yaml
GET  /api/doctor              环境自检结果
GET  /api/rows                表格行列表
GET  /api/row/{行}/images     这一行的图：找没找到、合不合规、要不要重出
GET  /api/row/{行}/thumb      这一行某张图的缩略图（给页面预览用）
GET  /api/fs/list             只读目录浏览（站内目录树的兜底）
POST /api/dialog/folder       弹系统「选择文件夹」对话框，回传路径
POST /api/dialog/file         弹系统「打开文件」对话框
POST /api/dialog/save         弹系统「保存」对话框
GET  /api/midou               米豆余额（只读；复制实测不扣，仅供参考）
POST /api/collect/scan        收集：只读扫描（收哪些行、跳过哪些）
POST /api/collect/run         收集：真的生成表格（永远是新文件，不覆盖）
POST /api/preflight           输入校验（表格 + 表里给的图片位置）
GET  /api/toolbox/probe       图片批处理生成清单自检（台账 / Pillow 能力）
POST /api/toolbox/{工具}/scan 工具箱预览（只读，一个字节都不写）
POST /api/toolbox/{工具}/run  工具箱执行（要 live:true）
POST /api/run                 起任务（默认干跑；真实执行要显式 live）
GET  /api/jobs/current        任务状态与步骤
POST /api/jobs/cancel         请求停止
GET  /api/logs                增量日志（轮询兜底）
GET  /api/logs/stream         SSE 实时日志
```
