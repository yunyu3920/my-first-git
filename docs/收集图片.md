# 收集图片（temu-bot collect）

把一个素材文件夹里的图，整理成一张「商品信息表」。代码在 `src/temu_bot/collect/`。

## 收集类型：默认**不搜子文件夹**

页面上「收集类型」有两个选项，默认是**「收集当前所选文件夹的图片（不搜子文件夹）」**：

| 选项 | 行为 |
|---|---|
| 收集当前所选文件夹的图片（默认） | 只看这一层，**快** |
| 连同所有子文件夹一起收集 | 递归往下走 |

默认不搜子文件夹有两个理由：一是符合这句话的本来语义（原工具的下拉里也是这个措辞）；
二是**性能**——递归是 `rglob` 走全树，实测选到「桌面」这种父目录要 **1 秒**，
不递归只要 **4ms**。

### 顺手修掉的一次重复扫盘

收集的扫描流程里，查主图规格时会把整个目录**又扫了一遍**（占了总耗时一半以上）。
现在扫描结果里带着已经建好的目录索引，规格检查直接复用，不再重复扫。

实测（真实素材目录 `C:\Users\A\Desktop\Temu`，198 张图）：

| | 改前 | 改后 |
|---|---|---|
| 选到正常素材目录 | 52 ms | **40 ms** |
| 选到「桌面」这种父目录 | **1006 ms** | **4 ms** |

接口端到端（含 98 行 JSON 序列化 + 网络）：**约 87 ms**。页面渲染 **1.7 ms**。
页面上会显示「用时 xx ms」，快不快一眼就能看出来。

## 配对规则

素材目录里的文件是**成对**的：

```
00742093597.jpg          ← 主图
00742093597-素材图.jpg    ← 它的素材图（主图名 + "-素材图"）
```

**一對图 = 一行商品。**

| 情况 | 处理 |
|---|---|
| 有主图 + 有素材图 | 收成一行 |
| 有主图、**缺素材图** | **用主图生成一张素材图**（默认），并在结果里标出来 |
| 只有 `-素材图` 没有主图 | 不当成行（它不是主图） |

> 2026-10-16 用户把默认从"缺就跳过"改成了**强制生成**（控制台的「强制生成素材图」
> 默认勾上，CLI 也默认开）。要回到旧行为：控制台取消勾选，CLI 加 `--no-force-material`。

素材图是按**名字**去目录里找的，所以大小写不同、扩展名不同（`.jpeg` / `.png`）
也认得出来——但**只认"去扩展名后名字完全一致"**，不做前缀猜测。

> 这里踩过一个坑：早先用了模糊匹配，导致"缺素材图"的行把**主图自己**当成了素材图，
> 于是本该跳过的行被收进来了。原因见 `imaging/resolve.py` 的 `find_by_stem`。

## 产出的表

20 列，与你现有那张表**逐格一致**（已实测比对 98 行 × 7 列全同）：

| 列 | 收集时填什么 |
|---|---|
| 1 文件夹路径 | 你选的素材文件夹 |
| 2 主图 | 文件名 |
| 8 素材图 | 文件名 |
| 9 一键生成SKU货号前缀编码 | 主图名去扩展名（那个 11 位 ID）——**上架时拿它当 SKU 货号填进商品**（见 `docs/上架主流程.md`） |
| 10 店铺名 | 你在页面上填的 |
| 11 模板产品SPUID | 你填的 |
| 12 主图索引 | 你填的 |
| 13 商品ID / 14 状态 / 17 中文标题 / 18 英文标题 / 19 SKC货号 | **留空**，等上架阶段回填 |

第 19 列只有勾了「以图片名作为 SKC 货号」才会填。

## 产出**永远是新文件**

目标文件已存在时**自动加时间戳另存**，绝不覆盖。

这条是硬规矩：素材目录里本来就可能躺着一张同名的表
（`C:\Users\A\Desktop\Temu\商品信息表.xlsx` 就是），一声不吭覆盖掉是最糟糕的事故。
页面会提前告诉你"这个文件已存在，会改名另存"，写完也会把最终路径报出来。

## 用法

```bat
:: 干跑：只报告会收成哪些行、跳过哪些，不写文件
temu-bot collect --dir "D:\素材" --shop "A hat tshirt" --template-spu 6255081762

:: 真的写出（缺素材图会用主图生成一张，这是默认）
temu-bot collect --dir "..." --shop "..." --template-spu "..." --live

:: 改回旧行为：缺素材图就跳过该行
temu-bot collect --dir "..." --shop "..." --template-spu "..." --no-force-material --live
```

控制台里在**「收集文件」**页操作，流程是「选文件夹 → 扫描预览 → 生成表格」，
生成后可以一键「用这张表上架」。

**店铺名与模板 SPU 会记住上次填的**（存在浏览器本地 `localStorage`，键
`temu_bot.collect.last`），下次打开自动带出来。从没填过时留空 —— 不拿配置里
那家"配了模板SPU"的店来凑数（配置是死的，那家店很可能早就停用了）。

## 图片文件名清单 → 自动填中英文标题（2026-10-17）

收集页多了一个「图片文件名清单（可选）」文件框。选了它，生成表格时会按
**图片名的 11 位 ID** 把标题填进第 17 列（中文）/ 第 18 列（英文）。

等价于用户原来的 Excel 公式：

```
=VLOOKUP(I2, 图片文件名清单.xlsx!$A:$B, 2, 0)
```

程序里做，但把公式的几个坑处理掉了：

| 坑 | 处理 |
|---|---|
| ID 有前导 0（`00128479653`），Excel 里数字/文本一混就对不上 | 一律按**文本**归一后精确比对，**绝不转 int** |
| 英文标题不在固定列（实际文件放在 J 列，中间 C–I 全空） | 自动在 C 列之后找第一格"有字母、没汉字"的 |
| **英文列整体比 ID 列错一行**（A1 是表头，J1 却已经是英文标题） | 检测到"第一个 ID 之前就有英文、且英文总数 = 数据行数"时，按顺序重新对齐，并在预览里提示 |
| 清单是导出的 GBK CSV | 自动试 UTF-8 / GBK / UTF-16 |
| 有 ID 在清单里找不到 | 留空，不报错；预览里列出是哪几个 |

实现：`src/temu_bot/collect/titles.py`（`load_title_list`、`TitleList.lookup`），
在 `scan_folder()` 里按 `row.sku_prefix` 查，`row_cells()` 写进 17/18 列。
CLI 对应参数：`temu-bot collect --title-list <清单路径>`。

**实测**：拿 `C:\Users\A\Desktop\yyy\图片文件名清单.xlsx` 对那 6 行，
中文 6/6、英文 6/6 与现有表里手工填的**逐字一致**（包括英文列错行的情况）。

## 没做的

- **「后缀排序列表」**：用户说平时用不到，所以**没有做**（参考图里有这个输入框）。
  它的本意大概是给"同款的第 2、3 张图"排顺序，需要时再加。
- **「收集类型」下拉**：只有"收集当前所选文件夹的图片"这一种，子文件夹会一起扫
  （`rglob`），因为实际素材目录是平的，没必要做成选项。
- **从文件名猜中文标题**：有些素材图的名字本身就是一段中文描述，理论上可以拿来当标题，
  但你实际用的目录里文件名是 ID——**现在改成从「图片文件名清单」按 ID 取**（见上一节），
  不靠猜。
