# 实操测试清单

给你一步步点着测。**先读「不要做的事」，那几条一碰就会出问题。**

---

## ⚠️ 不要做的事（重要）

### 1. 新行可以真跑了，但**第一次请先干跑**

图片上传已经接通（见 `docs/图片上传.md`）。真实跑一行「新建」商品时，工具会：

1. 复制模板 → 2. 把表里的主图/素材图**真的传到店小秘** → 3. **只换主图**
   （新主图顶到轮播第 1 位，模板的展示图保留不动）→ 4. 用表里第 9 列填 SKU 货号
   → 5. 改标题保存 → 6. 把商品ID/状态写回表格

所以**不会再出现"标题对、图片是模板的"错商品**了。而且还有一道兜底：换图一处都没写进
商品字段时，`APPLY` 会**直接中止**，什么都不会保存。

但**第一次仍然建议先干跑**：干跑会把每一步、每张图、标题的前后对照都摊给你看，
一眼就能确认没选错行、没配错图。

判断方法：行列表的**「商品」列**标着 `已有商品`（表里有商品ID）= 续跑，**不会复制**、
也**不会重复传图**；标着 `新建` = 会复制建新商品 + 传图换图。

### 2. 发品额度与旧店

- Temu 对每店有**每日发品额度**，满了只能次日或找买手提额。实测 `hat-tshirt` 店历史失败里
  有 **207 条是「每日发品额度已满」**（`创建商品数量超过当日额度，请于次日创建`）
  → **一次别发太多**。
- `A lovely costume` 已停用（它 Temu 侧的授权过期，**不用管**）。现在只用 `hat-tshirt`。

### 3. 不要把 `--live` 当成"试试看"

`--live` 会**真建出商品**、真写数据、真往图片空间传图。要试就用干跑。

（复制本身**不扣米豆**——实测过；但它会**真的建出一个商品**，而且跑完忘了写回
商品ID 的话，下次再跑就是**重复铺货**。）

## 3. 自动上架页 —— 逐项测

页面按 **①②③** 分了三块，从上往下走。

### 3.1 行列表

- 默认列出**当前表的所有行**（现在是 6 行，`C:\Users\A\Desktop\yyy\商品信息表.xlsx`）。
- 点表头左边的复选框 → 把**当前筛选出来的**行全选。
- 搜索框能搜**行号 / 中文标题 / 英文标题 / 店铺 / 主图 / SKU货号**。
- 状态筛选下拉 → 选「成功」「失败」等只留对应行。
- **「商品」列**：`已有商品`（表里有商品ID）= 续跑，不会复制；`新建` = 会复制建新商品。
- **「SKU货号」列**（新）：显示第 9 列的值，也就是上架时要填进每个 SKU 的货号。
  这列是空的会显示红色 **`缺`** —— **空的上不了架**（没有它就只能沿用模板的货号）。

### 3.2 预览（新）

勾选一行 → ③ 区上方应该出现：

- **这一行的真实主图缩略图**（能看出是不是你要的图）
- 店铺、状态、是否有商品ID
- **SKU 货号（第 9 列）**：有值标「会填进每个 SKU」；空的话标红并写明会被挡下
- 图片文件夹路径 + 里面有多少张图
- 每张图：找没找到、合不合规、要不要重出（例如 `1340x1784 → 1340x1785`）

**故意测**：把某行主图文件名改错一个字（测完改回来），再勾选它 →
缩略图位置应显示「无预览」，下面写明「找不到这张图」。

### 3.3 核对输入

点「核对输入」。期望（当前这张 6 行的表）：

```
信息表格：商品信息表.xlsx｜6 行
图片文件夹：C:\Users\A\Desktop\yyy｜12 张图
表格 6 行；图片文件夹 12 张图；可上架 6 行，被挡 0 行
```

**再故意测三种"该被挡"的情况**（每次测完改回来，或先备份表）：

| 改什么 | 期望 |
|---|---|
| 某行主图文件名随便改一个字 | 那一行出现在「会被挡下的行」里，原因「找不到」 |
| 某行**素材图**列清空 | 那一行被挡，原因「没有「素材图」」 |
| 某行**第 9 列**清空 | 那一行被挡，原因「第 9 列……是空的」 |

这证明"输入不齐就在碰接口之前挡下来"是真的生效，而且**控制台说的"可上架"跟上架流程的
`PRECHECK` 是同一套标准**（不会出现"控制台说能跑、跑起来却被挡"）。

### 3.4 店铺不用你管——程序自己认

**页面上没有登录身份下拉框、没有「核对店铺」、没有「打开店小秘」按钮**（按你的要求删了）。
核对是程序自己做的：拿表里第 10 列的店名，挨个问登录身份的账号里有没有这家店。

- 正常跑一行 → `SHOP_CHECK` 那条应显示
  `表里「X」↔ 登录身份「Y」（自动认出来的）↔ 账号里的店「X」(shopId=…)`。
- **故意测拦截**：把表里第 10 列**改成一家不存在的店**（记住先备份表），再干跑 →
  应显示 `没有任何登录身份的账号里有这家店`，并**列出查过哪些身份、那些账号里有哪些店**；
  同时顶部横幅弹出这条提醒，**并且自动打开了店小秘**好让你去处理。
  这一行不会复制、不会建商品。

### 3.4b 上架前先打开店小秘

**「上架前先打开店小秘」默认勾着**，点「开始」后会：

- **弹出一个浏览器窗口**（是这套工具自己的浏览器，不是你的日常浏览器），
  里面打开店小秘；**开哪个账号由程序按表里的店铺名决定**，横幅里会说明开了谁、为什么；
- 你可以在里面**确认店铺信息**、需要的话**登录**或**切换店铺**；
- 关掉窗口登录态会自动保存（关窗口之前每 5 秒已经存过了）；不关也行，最长 30 分钟收工。
- 同一个身份**重复打开**会被拦：「已经开着了」。

不想让它开就把勾去掉。

### 3.5 运行方式与几个默认开关

- 「运行方式」**默认就是「真实执行」**（按你的要求），所以「保存后的动作」下拉一进来就在。
  这个下拉也**默认「2 = 立即发布」**——点下去商品会**直接发到 Temu**。
  想先只看不发布，就切到「1 = 仅保存」（真跑时确认框里会把当前动作写清楚）。
- 切到**干跑** → 那个下拉消失（干跑不需要这个参数）；再切回来又出现。
- **真实执行点「开始」时仍会弹一次确认框**（写清要建商品、传图、写数据），
  因为默认就是真实，这一下确认别去掉——它能挡住点错。
- **默认值（按你的要求）**：
  - **「选择要跑的行」默认全选** —— 进来就全勾上，你取消不想跑的。
    动过勾选之后就不会再自动全选（比如你取消了两行，再刷新不会又勾回来）。
  - **「强制换图」默认勾上** —— 每一行都重传图换图，包括表里已有商品ID 的"续跑"行。
  - **「自动清理图片」默认勾上** —— 真实上架成功后才删 `work/<行>/` 的中间产物；干跑绝不清理。
  - 「上架前先打开店小秘」默认勾上（见 3.4b）。

### 3.6 干跑（核心）

**先手动把「运行方式」切到「干跑」**，勾一行（页面进来就默认全选，把不想跑的取消掉），
点「开始」。下面拿**表里第 2 行**举例（行号/店名/模板 SPU 以你当前表为准）：

期望：状态条 `空闲 → 运行中 → 已完成`；③ 区出现**蓝色横幅**「已完成：共 1 行，成功 1，
失败 0（干跑，未写任何数据）」；进度条走满；结果区出现「第 2 行 成功」和九步：

```
PRECHECK       00128479653.jpg｜素材图 …｜模板SPU 6255081762｜标题「…」
MEDIA          主图 cover 1340x1784 → 1340x1785；素材图 已合规（800x800）
SHOP_CHECK     表里「SWEET SHIRT SHOP」↔ 登录身份「hat-tshirt」（自动认出来的）↔ 账号里的店 shopId=8665618
FIND_TEMPLATE  找到模板 id=…（在这家店里搜到的）
COPY           表里已有商品ID …，跳过复制（再复制=重复铺货）
FIND_NEW       沿用表里已有的商品ID …
UPLOAD         表里已有商品ID …，不重复上传图片（要强制换图用 --swap-images）
APPLY          标题与目标一致，且只要求保存，无需修改
WRITEBACK      （干跑）届时把商品ID 与状态写回表格
```

> 最后一步 `WRITEBACK` 是**跑完把商品ID/状态写回表格**——这是防重复铺货的闸门，
> 跑一行就锁一行。干跑时它只显示"届时会写什么"，**一个格子都不动**。

**再看一行的 UPLOAD**：找一行标着「新建」的来干跑（或用 CLI 加 `--row-index`），
`UPLOAD` 应该显示这样的内容：

```
将上传 2 张（main-….jpg、material-….jpg）：
  主图 1 张 → 顶到轮播第 1 位 + SKU 缩略图；素材图 1 张 → 素材图位；
  模板的 4 张展示图保留不动
```

`APPLY` 应该带上：

```
换图：轮播图 5 张 → 5 张（新主图 1 张排第 1，保留展示图 4 张；模板原来的主图删掉）；
      SKU 缩略图 1 条 → 新主图；素材图 → 换
SKU货号 99689509419 → 00128479653
```

——**干跑只说要传什么、改什么，一张图都不会真传、一个格子都不会动**。

同时右侧日志**实时**滚动出现同样的内容。

### 3.7 干跑确实没写东西

### 3.8 店铺不对时会被拦下（安全闸一）

期望：跑到 `SHOP_CHECK` 就**停下**，提示「表里要上「不存在的店」，但没有任何登录身份的

### 3.9 换图的安全性（安全闸二）

换图不会静默失败，两道都测一下：

1. **商品里没有可写图片字段** → `APPLY` 应该 `FAIL` 中止，提示「上传成功了，但商品里
   找不到可写的图片字段……已中止」，`save_product` **不会被调用**。
   （单元测试钉住：`tests/test_listing.py`）
2. **缺素材图的行** → `PRECHECK` 直接失败：「没有「素材图」（缺素材图的行请先跳过，
   别硬上）」，**一次接口都不发**。
   实测方法：随便找一行，把它的素材图列清空（记住先备份表），再干跑它。

### 3.9b 回写表格被 Excel 挡住时会怎样（重要）

**测法**：用 Excel/WPS 打开商品信息表 → 真跑一行（或跑 `temu-bot run ... --live`）。

期望：

- `WRITEBACK` 那一步显示 **❌**，写明「表格被占用，没写回：…」并给出补写命令；
- **但这一步的失败不算"上架失败"**——结果区那一行仍然显示 ✅ 成功。
  因为商品已经建好了，说"失败"会诱使你去重跑，那正好造成重复铺货；
- 网页控制台顶部会**单独弹一条横幅**，点名是哪几行没写回。

然后**关掉 Excel**，补写：

```bat
temu-bot table writeback                      :: 先干跑看一眼将要写什么
temu-bot table writeback --live
```

期望写回后表里第 13 列有商品ID、第 14 列是 `成功`，备份出现在 `data\backups\`。
