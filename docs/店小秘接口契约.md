## 0. 认证与请求约定

- 认证：**cookie**（`data/state/session_<店铺>.json` 里的 `JSESSIONID`、`dxm_vc` 等）。
- 请求头：`content-type: application/x-www-form-urlencoded`（前端统一用 `postForm`）；
  `referer` 指向对应前端页（如 `https://www.dianxiaomi.com/web/popTemu/edit?id=<商品id>`）。
- **没有 CSRF token 头**（JS 里所有写接口都只带 cookie）✅
- 返回外壳统一：`{"code":0,"msg":"Successful","msgCode":null,"data":{...}}`；
  未登录时 `code=2001, msg="验证失败了", data=null` ✅（`verdict_of()` 已实现该判定）

### 保存商品 ✅（已实测跑通，2026-10-15）

```
POST /api/popTemuProduct/add3f8c2a97.json        ← 注意路径里那段固定 token
Content-Type: multipart/form-data
  file = 一个 **zip**（deflate 压缩，内含唯一条目 choiceSave.txt = 扁平载荷的 JSON）
         字段名 file，文件名 blob
  op   = 1 保存 | 2 立即发布 | 3 保存并移入待发布 | 5 定时发布
→ {"code":0,"msg":"您的产品已保存成功！","data":"<店小秘商品id>"}
```

**坑（踩了三次）**：
1. 不是普通 form——参数藏在**文件**里
2. 文件不是纯 JSON，是 **zip**；直接传 JSON 会得到 `保存对象转换异常`
3. 载荷**不是** edit.json 里的 149 字段商品对象，而是**扁平的 39 个字段**，
   多数 id 类字段要由 int 转成 **字符串**（见 `DxmClient.SAVE_FIELD_TYPES`，
   字段表与类型全部由抓包推导，`build_save_payload()` 负责转换）

已验证闭环：读商品 → 归一化英文标题 → 保存 → **服务端回读确认改动生效**。

### 商品对象里的几个关键字段（`edit.json` 返回）✅

对着真实商品逐个核过：

| 字段 | 形态 | 是什么 |
|---|---|---|
| `mainProductSkuSpecReqs` | **JSON 字符串** | SKC 级规格：每条含 `parentSpecName`(颜色)/`specName`/`extCode`/`previewImgUrls`(竖线拼多张轮播) |
| `mainProductSkuSpecReqsList` | **真列表** | 同上内容的镜像 |
| `variationListStr` | **JSON 字符串** | SKU 级：每条含 `extCode`(SKU 货号)/`thumbUrl`/`productSkuSpecReqs`(颜色+尺码)/价格库存尺寸… |
| `variations` | **真列表** | 同上内容的镜像 |
| `materialImgUrl` | 字符串 | 素材图（顶层单个） |

**注意同一份数据有"字符串"和"列表"两种形态**（`…List` / `variations` 是真列表）。
改的时候两种都要兜住，否则会静默失败——见 `imaging/swap.py` 与
`product.as_list_field` / `set_list_field`。

**货号 `extCode` 有两个层级**（实测老工具上架成功的 98 个商品）：

| 层级 | 字段 | 谁填 |
|---|---|---|
| SKC 级 | `mainProductSkuSpecReqs[*].extCode` | **模板自己的**（如 `ZD001`），工具不动 |
| SKU 级 | `variationListStr[*].extCode` | **表里第 9 列**，同一 SKC 下所有尺码同一个值 |

⚠️ 别把这两个搞混：SKC 级是"这一色号的货号"，SKU 级是"这一规格的货号"。

## 6. 拟定流程（复制模板 → 改 → 发布）

```
1. POST /api/banjia/copyProduct.json   {shopIds, productId(模板), platform, hidePrice:"0"}
2. POST /api/popTemuProduct/pageList.json (dxmState=offline)   ← 找到刚复制出来的新商品
   （原工具专门处理过"复制成功但待发布列表里找不到新商品"）
3. GET  /api/popTemuProduct/edit.json?id=<新商品id>            ← 拿完整商品对象
4. 上传图片：getSign → PUT → cosDxmCallBack
5. 改标题/图片/SKU货号 → 保存（接口待确认）
6. POST .../batchPublish.json  {ids}                            ← 发布
```
