# 店小秘改版了怎么办

目标：**不跑到一半才发现接口没了**；发现后**改配置或小补丁就能恢复**。

## 先搞清一件事

这个程序**不点页面**：登录用 Playwright 拿一次 cookie，之后所有业务都走店小秘的
`/api/*.json`（见 `docs/店小秘接口契约.md`）。所以：

| 店小秘改了什么 | 会不会影响上架 |
|---|---|
| 换布局、换按钮、换颜色、换 CSS | **基本不影响**（程序不看 DOM） |
| 接口路径改名 | 会影响 → 改 `config/dxm_endpoints.json` 就能修 |
| 接口参数/返回结构变了 | 会影响 → 需要改 `src/temu_bot/dianxiaomi/client.py`（AI 可以代劳） |

## 程序已经会自动做的三件事

1. **候选端点自动切换**：每个操作可以配多个路径，前一个 404/405 就换下一个
   （例如图片删除：`/api/album/delPic.json` → `/api/cos/deletePic.json`）。
2. **开跑前接口自检**：点「开始」时，先只读探活 `userIn` / `pageList` / `album`。
   哪一项变了就 **409 停住，一行都不跑**——不会出现"复制了一堆商品但保存全失败"。
3. **失败留证**：批次里只要有一行踩到 404/405，就在
   `data/reports/diagnose/<时间戳>-site-changed.json` 写一份报告
   （哪一行、哪一步、哪个端点、返回了什么）。

## 发现改版后怎么做

### 第 1 步：跑自检

```powershell
cd D:\temu_bot
.\.venv\Scripts\python.exe -m temu_bot.cli diagnose api --deep
```

控制台里也能点：上架页 →「店铺核对」那一块的 **「接口自检」** 按钮。

输出示例：

```
│ 商品列表 pageList │ FAIL │ 疑似接口变更：... HTTP 404 │ /api/popTemuProduct/pageList.json │
```

### 第 2 步：只是路径变了 → 改 JSON（不用重新打包）

打开 **`config\dxm_endpoints.json`**，把新路径加到候选列表最前面：

```json
{
  "product_list": ["/api/popTemuProduct/newPageList.json",
                   "/api/popTemuProduct/pageList.json"]
}
```

改完重开程序，再跑一次 `diagnose api`。打包版改 `temu-bot\config\dxm_endpoints.json`。

> 配置文件写坏了也不会影响启动——程序会回落到内置默认。

### 第 3 步：结构变了 → 让 AI 用 Scrapling 看一下

Scrapling 已经装进本项目的诊断环境（**不进绿色包**）：

```powershell
uv sync --group diagnostics        # 装 Scrapling（只在本机用）
```

并注册成了 MCP（Cherry Studio → 设置 → MCP → `scrapling`）。
它的工具里最有用的是：

- `browser_open` / `browser_fetch`：用隐身浏览器打开店小秘页面；
- `browser_load_state`：载入已保存的登录态；
- 会话里能看**网络请求历史**——对着新页面点一遍，就知道新接口/新字段叫什么。

让 AI 做的事：打开出问题的页面 → 抓一遍新请求 → 对比
`docs/店小秘接口契约.md` → 改 `client.py` → 跑测试。

### 第 4 步：自己抓包（不依赖 AI）

现成的录制器（Playwright）：

```powershell
.\.venv\Scripts\python.exe -m temu_bot.cli record --shop hat-tshirt --goto https://www.dianxiaomi.com/web/popTemu/pageList
```

产物：`data/reports/recording/<时间戳>.jsonl` + `-bodies/`（响应体）。
cookie / authorization 等敏感头的值不会落盘，只记名称。

## 边界（必须知道）

- **路径级变化**：改 `dxm_endpoints.json` 就能恢复，不用重新打包。
- **结构级变化**：需要改代码；Scrapling/MCP 只是让"定位 + 修改"变快，
  不是自动改写程序。
- **不保证任意改版零报错**：程序能做到的是"不静默跑坏、快速定位、改小补丁恢复"。

## 相关命令

```powershell
# 接口自检（只读）
.\.venv\Scripts\python.exe -m temu_bot.cli diagnose api [--shop 登录身份] [--deep]

# 环境自检（离线，不碰网络）
.\.venv\Scripts\python.exe -m temu_bot.cli doctor [--json]

# 抓包（打开页面后录 XHR）
.\.venv\Scripts\python.exe -m temu_bot.cli record --shop hat-tshirt --goto <页面地址>
```

## 打包时的注意（很重要）

`patchright`（Scrapling 的浏览器引擎）会在 site-packages 里放一份
**Playwright 的 PyInstaller hook**，PyInstaller 打包时会跟着把它的
102 MB 驱动一起收进去——绿色包会从 187 MB 涨到 289 MB。

所以打包前后要这样切：

```powershell
# 1) 只留 packaging 组：会把 Scrapling/patchright 卸掉（正好）
uv sync --group packaging

# 2) 打包（187 MB）
.\.venv\Scripts\python.exe tools\build_app.py

# 3) 装回 Scrapling，MCP 恢复可用
uv sync --group packaging --group diagnostics
```

`tools/build_app.py` 里也加了 `--exclude-module scrapling/patchright/curl_cffi/lxml`，
但 hook 仍然会生效，所以**第 1 步不能省**。
