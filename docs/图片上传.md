# 图片上传（怎么把图传进店小秘、怎么换到商品上）

代码：`src/temu_bot/dianxiaomi/client.py` 的 `upload_image()`，
换图逻辑在 `src/temu_bot/imaging/swap.py`。

## 三步上传

店小秘的图片空间是腾讯云 COS，走**签名直传**，三个接口按顺序：

```
1) POST /api/cos/getSign.json          ← 要签名（form 参数：bucket / region / fileName）
2) PUT  https://<COS 直传地址>          ← 真传字节（Authorization: <sign>）
3) POST /api/cos/cosDxmCallBack.json   ← 登记，店小秘才认这张图
```

对应 `DxmClient.upload_image(path)` 内部：

| 步骤 | 方法 | 说明 |
|---|---|---|
| 要签名 | `cos_get_sign_for(file_name, bucket, region)` | 返回 `sign` / `url` / `fileId` 等 |
| 传字节 | `cos_put(sign, url, content, content_type)` | 普通 `PUT`，把文件原样发过去，不带额外表单字段 |
| 登记 | `cos_register(file_id=..., file_name=..., file_size=...)` | 不登记等于白传 |

**参数是实探出来的**，不是猜的：`bucket` + `region`（默认 `wxalbum` / `ap-shanghai`），
**没有** `fileType` 这个字段（一开始以为有，是错的）。

`upload_image()` 返回原始响应再补上两个键：

```python
{... , "fileId": "...", "cosUrl": "//wxalbum-....cos.dianxiaomi.com/..."}
```

`cosUrl` 是**协议相对地址**（以 `//` 开头），拼进商品前要补 `https:`。

## 换图：换法 + 写到哪几个字段

### 换法（2026-10-16 用户定的规矩）

`previewImgUrls` 是竖线拼的列表，**第 1 张是主图、后面几张是展示图**。换图时：

> 把模板的主图**删掉**，新的主图**顶到第 1 位**，模板的**其它展示图原样保留**。

```
模板：[主图A, 展示1, 展示2, 展示3, 展示4]
            ↓ 换
结果：[新主图, 展示1, 展示2, 展示3, 展示4]
```

**只换主图，绝不删展示图。** 保留的这几张以**模板商品**为准（流程会专门去读一次模板，
见 `ListingPipeline._template_showcase`）——万一这个商品之前被换错过、展示图已经丢了，
从它自己身上取是取不回来的。

SKU 缩略图（`thumbUrl`）跟着换成**新主图**（就是第 1 位那张）。

**颜色/规格一个字都不动**：`parentSpecName`（颜色）、`specName`、`productSkuSpecReqs`
原样保留，只改图片地址。有测试钉住（`tests/test_swap.py` 的
`test_colors_and_specs_are_left_untouched`）。

### 字段

> **最大的坑：这几个字段在接口里是 JSON 字符串，不是对象。**
>
> ```python
> product["mainProductSkuSpecReqs"] == '[{"previewImgUrls":"a.jpg|b.jpg", ...}]'   # 字符串！
> ```
>
> 直接 `product["mainProductSkuSpecReqs"][0]["previewImgUrls"] = ...` 会炸；
> 当字符串原样改又改不到里面那一层，结果是**保存下去图片没换、却毫无报错**。
> 所以统一走 `imaging/swap.py`，两种形态都处理。

| 位置 | 字段 | 怎么写 |
|---|---|---|
| 轮播图 | `mainProductSkuSpecReqs[*].previewImgUrls` | `新主图 + 模板展示图`，用 `\|` 拼 |
| 镜像字段 | `mainProductSkuSpecReqsList[*].previewImgUrls` | 同上 |
| SKU 缩略图 | `variationListStr[*].thumbUrl` | 用新主图 |
| 镜像字段 | `variations[*].thumbUrl` | 同上 |
| 素材图 | `materialImgUrl` | 顶层单个字段 |
| SKU 货号 | `variationListStr[*].extCode` | 表里第 9 列（见 `docs/上架主流程.md`） |
| **不动** | `parentSpecName` / `specName` / `productSkuSpecReqs` | **颜色与尺码，一律不碰** |
| **不动** | `mainProductSkuSpecReqs[*].extCode`（SKC 级的货号） | 保留模板自己的 |

**只写商品本来就有的字段。** 接口对不带某个键的商品，多半会忽略我们塞进去的值——
那图片就白传了。所以：

- 一个字段都没写进去 → `patch_product_images()` 返回的结果为假 →
  `APPLY` 步直接 `FAIL` **中止**，不会存下一个"标题对、图片是模板的"错商品。
- 轮播换上了、但商品没有 `materialImgUrl` 字段 → 算成功，同时**留一条告警**
  让用户看见（不会凭空塞一个字段进去）。

## 干跑与真实

- **干跑**（不加 `--live`）：`UPLOAD` 只报告"将上传 N 张（哪几张）、分别去哪个位"，
  **一张都不传**，`getSign` 也不会被调。
- **真实**：先传图，再在保存前把地址写进商品对象。任一步失败就停，不保存。

已有商品ID 的行默认**不换图**（那是重试/续跑）。要强制换加 `--swap-images`。

## 发布成功后清理图片空间（2026-10-18）

店小秘图片空间有容量上限，传多了会满（满了连 `getSign` 都取不到签名）。
勾着「自动清理图片」时，**`op=2 立即发布` 且这一行成功后**，会把这次传上去的图
从图片空间里删掉：

```
POST /api/album/delPic.json        form: ids=<idStr>,<idStr>,...
GET  /api/album/list.json          ?name=<文件名> → idStr / imgUrl / lockState
```

实现在 `web/album_clean.py`：

- **只删这次上传的**：拿 `ListingOutcome.uploaded_urls`，按 **COS 路径**
  在空间列表里精确匹配。同一个文件名以前传过的老图（路径不同）不会命中。
- `lockState != 0`（锁定）的跳过。
- **`op=1 仅保存` / `op=3 移入待发布` 不删**：商品还是草稿，删了图会把草稿弄坏。
- 删失败只记日志，不影响上架结果。
