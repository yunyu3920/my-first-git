# 打包与发布

把程序变成**绿色免安装目录**，拷到别的 Windows 电脑双击就能用；
以及怎么把它推到 git 仓库、以后怎么迭代。

## 一、打包

```powershell
cd D:\temu_bot
uv sync --group packaging                                  # 装一次 PyInstaller
.\.venv\Scripts\python.exe tools\build_app.py              # 打包
```

产物在 **`dist\temu-bot\`**（约 187 MB）：

```
dist\temu-bot\
├─ 启动 temu-bot.bat      ← 双击这个（主入口）
├─ 1-登录店小秘.bat         首次使用 / 换账号时用
├─ 使用说明.txt
├─ temu-bot.exe          程序本体（命令行入口，一般不用直接点）
├─ config\config.yaml     配置（照抄你本机那份，新电脑上按需改路径）
└─ _internal\            PyInstaller 带的 Python 运行时与依赖，别动
```

第一次运行时会自己建 `data\`、`work\`、`profiles\`——**日志、备份、ID 台账、
登录态**都在 `data\` 和 `profiles\` 里。

### 为什么是"一个文件夹"而不是一个 exe

- 单文件 exe 每次启动都要把自己解压到临时目录，**慢**；one-dir 直接跑。
- Playwright 自带一个 node 驱动器，这类"库里面还带二进制"的，单文件模式容易出怪问题。
- 拷给别人时把整个文件夹压成 zip 就行，用起来没差别。

### 新电脑上要准备什么

| 要什么 | 说明 |
|---|---|
| **Google Chrome** | 要装。登录店小秘用的是**系统 Chrome**（`browser.channel: chrome`），不是打包自带的浏览器——这样登录窗口就是你熟悉的样子 |
| Windows 10/11 | 目标平台就是它 |
| ~~Python~~ | **不用装**，运行时已经打进 `_internal\` 了 |
| ~~Node~~ | **不用装** |
| ~~WPS / Excel~~ | **不用装**（Excel 合并走 openpyxl） |

### 换电脑后要改的地方

打包时 `config\config.yaml` 是**照抄你本机那份**的，里面写死了
`C:\Users\A\Desktop\...` 这类路径。到新电脑上：

1. 双击 `启动 temu-bot.bat` 打开控制台；
2. 进「设置 → 路径」，把**商品信息表**改成新电脑上的路径 → 保存
   （这只写 `config\config.local.yaml`，不动主配置）；
3. 「环境自检」跑一遍，确认都 PASS。

`config.yaml` 里的 `toolbox.app_dir` / `ledger` 指向桌面那个旧工具箱——新电脑上没有
也无所谓，它只用来把旧 ID 台账合并进来，缺了就当 0 个。

### 升级到新版

**把新版整个文件夹覆盖过去，但保留 `config\`、`data\`、`profiles\` 三个目录。**
它们是你的数据（配置、台账、登录态），程序本体可以随便换。

> 注意：`data\state\` 里有**店铺登录态**（`session_*.json`），`profiles\` 里有浏览器
> 配置。**这两个目录别外传、别提交到 git。**

## 二、推送到 git 仓库

仓库已经建好了（`D:\temu_bot\.git`），首次提交也完成了。第一次推送：

```powershell
cd D:\temu_bot
git remote add origin <你的仓库地址>     # 例如 https://github.com/你/temu-bot.git
git branch -M main
git push -u origin main
```

推送要你自己的账号凭据，我这边给不了。仓库是**空仓库**最好；如果建的时候自动生成了
README/LICENSE，先 `git pull --rebase origin main` 再推。

### 首次提交的作者信息

提交时的作者写的是占位的 `A <A@users.noreply.github.com>`。想换成你自己的，
**在 push 之前**改掉最省事（还没推出去，改完没痕迹）：

```powershell
cd D:\temu_bot
git config user.name "你的名字"
git config user.email "你的邮箱"
git commit --amend --reset-author --no-edit
```

### 为什么不把整个项目都提交

`.gitignore` 里有几类**故意不提交**的东西：

| 不提交 | 为什么 |
|---|---|
| `data/state/`、`profiles/` | **店铺登录态**（cookie）。提交上去等于把账号交出去 |
| `config/config.local.yaml` | 本机私密覆盖层（AI key 等） |
| `data/logs/`、`data/backups/`、`work/` | 运行期产物，没意义还很大 |
| `.venv/`、`dist/`、`build/` | 环境和打包产物，能重装/重打 |
| `*.bak-*` | 工具箱备份的旧清单 |

**第一次提交前已经核对过**：181 个文件里没有登录态、没有本地配置、没有打包产物。

### 以后怎么迭代

```powershell
cd D:\temu_bot
git add -A
git commit -m "说清楚这次改了什么"
git push
```

打新版：改完代码跑一遍 `tools\build_app.py`，再把 `dist\temu-bot\` 覆盖到目标机器
（记得保留 `config\`、`data\`、`profiles\`）。

**每次改完记得跑测试**：

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
```

## 三、打包时踩过的两个坑（别再踩）

1. **`doctor` 的「依赖包」在打包版里会误报"缺少"**。
   PyInstaller 打出来的包**没有 `.dist-info` 元数据**，`importlib.metadata.version()`
   一律查不到。已改成打包版走 `importlib.util.find_spec()` 判断模块导不导得进来。
   （顺带：`pillow` 的 import 名是 `PIL`、`psd-tools` 是 `psd_tools`，名字对不上也会误报。）

2. **前端静态文件得显式带上**。`web/app.py` 是按 `__file__` 旁边的 `static/` 找的，
   打包后纯 Python 模块可能被塞进 zip，那个路径就不存在了。现在 `_static_dir()`
   会再试一次 `sys._MEIPASS`。

3. **`psd-tools` 没打进包**——现在没有任何代码用它（PSD 套图还没做），
   PyInstaller 只收真正 import 到的东西，所以它不在包里。`doctor` 把它标成"可选未装"。
   哪天真用上了，在 `tools/build_app.py` 里加 `--collect-all psd_tools` 再重新打包。
